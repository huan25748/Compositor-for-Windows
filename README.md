# Compositor for Windows

Mac 版 [Compositor](https://github.com/robbietilton/Compositor)（"The Photoshop alternative for Mac"，MIT 许可）的
**Windows 复刻版**。

上游是 Swift + SwiftUI + Metal 的原生应用；本复刻用 **Electron + TypeScript + WebGL2**
重写了它的图层合成引擎，并把界面完整本地化为**简体中文**。

最关键的一点：本程序**读写与 Mac 版完全互通的 `.comp` 项目格式**（官方 schema 版本 1–11）。

---

## 快速开始

```powershell
cd compositor-win
npm install
npm start        # 构建后启动
```

其它命令：

```powershell
npm run build       # 只构建（esbuild 打包主进程 / 预加载 / 渲染进程）
npm run typecheck   # TypeScript 类型检查
npm test            # 单元测试（.comp 读写、混合模式数学、校验规则）
npm run dist        # 打包 Windows 安装包（需要 electron-builder）
```

> 若 `npm install` 时提示 `esbuild` / `electron` 的安装脚本未执行，
> 运行 `node node_modules/electron/install.js` 以取得 Electron 二进制。

## 更新记录

### v1.2.0

图层效果这一版的重点是**描边**，另外补上了**渐变叠加**。

- **修复「部分字体切换不成功」（回归）**。根因是**测量的回退链与渲染的不一致**：
  过滤字体时测的是 `"名字", "__no_such_family__", sans-serif`（回退到 sans-serif），
  而渲染实际用 `"名字", "Microsoft YaHei UI", …`（回退到微软雅黑）。名字无效时两者回退到
  **不同字体**、宽度自然不同，于是被**误判成「有效」**——这些字体进了列表，但一选就回退。
  现在测量与渲染共用同一条回退链：`下拉框 370 项、选了不生效的 0 项`（此前有 1 项）。
- **效果对话框四处修正**：重复的「描边」标题（通用 toggle 行被 push 了两次）、
  「颜色叠加颜色」过长改为「叠加颜色」、滑块右侧的数字框改用 `numberInput`（原先还是原生箭头）、
  **勾选效果后无需重开对话框即可调节**（参数区按新状态重建）。

#### 效果对话框的四处修正

- **「描边」标题重复了一次**（一个带勾选框、一个没有）：通用的开关行已经在公共流程里 push 过，
  描边的专用分支里又 push 了一遍。删掉多余的那次。
- **「颜色叠加颜色」跨行**：改成「**叠加颜色**」。
- **滑块右侧的数字框还是原生箭头**：`slider()` 里那个数字显示框一直是裸的 `input[type=number]`，
  没走 `numberInput()`。现在改用它，箭头与别处统一。
- **勾选效果后不能立刻调参数**，得点「完成」再进来一次：参数区是按「当时是否启用」渲染的。
  现在勾选后会**重开一次对话框**，让参数区按新状态重建。

- **补齐数字框在其余场景下的样式与位置**（两处都漏了）：
  - **图层面板右上角的「不透明度」** 是 `index.html` 里**手写**的 `<input type="number">`，
    没走 `numberInput()`，所以既没有包装、也没有箭头，样式还和别处不一致。
    现在它的结构也补上了步进按钮。
  - **对话框里的数字框箭头落在中间**：输入框固定 62px 宽，而对话框的容器很宽，
    箭头就停在三分之一处。现在 `.field` / `.prop-row` 内的数字框改为**撑满容器**，
    箭头贴右边缘（探针实测离右缘 4px、输入区 303px）。
  - 顺带把步进按钮改成**事件委托**（`installNumberSteps()`）：手写的与 `numberInput()` 生成的
    走同一条逻辑，按钮只需带 `data-dir`。

- **数字框改为「真按钮」版本的箭头**：既保留自绘样式，又真的能点。做法是 `numberInput()` 返回一个
  包装元素（输入框 + 两个 `<button>`），并在包装上遮蔽 `value` / `addEventListener` 转发给内部
  输入框 —— 因此 17 个调用点一行都不用改。按钮点击会改值并派发 `change`，原有监听器照常触发。
  - **不要用 Proxy 包装 DOM 元素**：`append()` 要求参数是真 Node，Proxy 会被当成字符串，
    输入框根本进不了 DOM（这一步已踩过，改用 `Object.defineProperty` 在真元素上遮蔽成员）。
  - 这一版**可自动验证**（真按钮有命中区域）：探针实测「48 → 点▲ 49 → 点▼ 48」。
    而之前基于伪元素的几种做法探针读不到，只能靠肉眼。

- **修掉「箭头点不了」**。上一版的做法是错的：自绘一对白色三角当背景图，再把原生箭头设成
  `opacity: 0` —— 结果**两个都不能点**（背景图本来就没有命中区域，而透明后的原生箭头也不响应）。
  现在改用最直接的方式：**就用原生箭头**，只加 `filter: invert(1)` 把它的颜色反成白色
  （CSS `filter` 对伪元素是生效的 —— 我之前没试就假设它不行，这是我的疏忽）。
  底仍是纯黑，外观统一，点击也正常。
  说明：「箭头能否点中」属于伪元素行为，探针读不到，只能靠肉眼确认 —— 这一项自动化覆盖不到。

- 数字框进一步统一为**纯黑底 + 白色箭头**。原生 spinner 的颜色无法设置，所以改为**自绘**：
  用 `background-image` 画一对白色三角，把原生箭头设成 `opacity: 0` 藏起来 —— `opacity` 为 0
  不影响它的命中区域，因此点击加减依然有效。新增断言：背景图必须存在（`箭头=true`）。

#### 把数字框的上下箭头加回来

- 上一轮统一控件外观时，我用了 `appearance: textfield` 去掉数字框的原生上下箭头 —— 那条规则
  **同时也把箭头隐藏了**，等于砍掉了一个常用操作（点一下 +/- 微调）。
- 现在不再设它：箭头恢复，而边框、背景、高度仍由我们自己的规则指定，所以**外观照旧统一**。
  箭头本身用 `opacity: 0.5` 压低对比度（悬停提亮），免得在深色界面上过于刺眼。
  探针断言也相应改成「`appearance` 不能是 `textfield`」—— 之前那条正好写反了。

#### 文字工具新增「字重」

- **背景**：同一字体族常常打包多种字重（如「阿里巴巴普惠体 3.0」就有 35 Thin / 55 Regular /
  105 Heavy…），而 CSS 只能按「**族名 + font-weight**」去选 —— 直接写全名「…105 Heavy」是无效的。
  这也是字体列表里同族只剩一个条目的原因：那些名字被剥离成同一个族名后合并了，字重信息丢失。
- 现在顶栏加了**字重选择器**（100 极细 … 400 常规 … 900 极粗），写入文字元数据的 `fontWeight`，
  渲染时拼进 `ctx.font`（`<weight> <size>px "<族名>"`）。族内没有该字重时由浏览器合成加粗。
- 编辑框（textarea）也同步字重，否则它的字形宽度与画布不一致，光标同样会对不上。
  探针实测：常规 → 900 后字形宽度由 135 变为 142。
- 字重是**整层**属性（不像字号可分段），因为 CSS 的字体选择本身是按族 + 字重的。

#### 修复「改字号后光标定位不准」

- **根因**：编辑框（textarea）只能有一个字号，而富文本下每个字符的字号可以不同（`sizeRuns`）。
  原先它固定用**整层字号**，所以只把选中那部分字放大后，编辑框仍是旧字号 —— 拖选时光标就按
  旧字号算位置，对不上画布上的字。
- **修法**：编辑框字号跟随**光标所在字符**的字号（`charStyles()` 取该处样式）。整层字号一致时
  行为与原来完全相同；只有混排字号时才会有差异，而那正是需要对齐的场景。
- 探针实测：整层改到 96 → 编辑框 78px；再选中一部分改到 24 → 编辑框降到 19.5px（= 24 × 缩放）。

#### 鼠标指针按工具区分

- 此前画布上**所有**工具都是同一个十字（`cursor: crosshair`）——选了画笔、橡皮还是魔棒，
  指针一模一样，分不清手里拿的是什么。现在：**除抓手与缩放外，指针都是「暗色箭头 + 右下角
  缩小的工具图案」**（`ui/cursors.ts`）——箭头保持用户熟悉的形状与落点（尖端就是热点），
  右下角的角标提示当前拿的是哪个工具；图案按 24×24 设计稿绘制，用 Canvas 的 `Path2D`
  画成 32×32 的 PNG 位图再交给 CSS（`url(位图) 热点, 关键字`）。
  抓手用系统的 `grab` / `grabbing`，按住空格临时平移时也是 `grab`；缩放保持放大镜图案本身
  作为指针（放大镜的形状已经说明了用途）。
- 配色是「深色填充 + 白色细描边、角标用深色圆底 + 白色图案」：浅色纸张与深色画布上都看得清。
- **两个坑都是实测踩出来的**：
  - 先试的「把 SVG 光栅化成光标」在 Electron 里画出的是**整幅透明**的位图
    （探针一数：不透明像素 0），而 Chromium 照样接受它 —— 用户表现就是「鼠标进了画布却没有指针」。
    现在改用 `Path2D` 直接绘制，并加了**空白即弃用**的检查：图案没有可见笔画就退回关键字。
  - 指针写在 CSS 变量 `--tool-cursor` 上，而不是直接写 inline `cursor` —— 后者会盖掉
    `.panning` 的 `grabbing`，拖动平移时光标还停在工具图标上（原先空格的逻辑就有这个毛病）。
- 自检逐个切换工具比对 computed `cursor`，并把每张位图**解码后数像素**（非透明 / 白色 / 暗色）：
  **16 个工具 16 种指针、14 个是暗色箭头 + 角标、无一是十字、没有一张空白图案、主体都是暗色**，
  且平移中为 `grabbing`、按住空格为 `grab`、松开空格回到当前工具的指针。

#### 画布滚动条与两轴滚轮

- 画布区新增**左右 / 上下两条滚动条**：滑块长度与位置按「视口 / 内容」的比例计算
  （`scroll.ts` 的纯函数，含最小滑块长度与两端夹紧），拖动滑块或点击轨道即可调整显示位置；
  内容不比视口大时整条隐藏。拖动监听挂在 `window` 上而不是靠 `setPointerCapture` ——
  后者在合成事件与部分设备上不生效，表现就是「拖不动」。
- **滚轮两轴平移**：竖滚＝上下移动，**Shift + 竖滚＝左右移动**（普通鼠标只有一个滚轮），
  触摸板与横向滚轮的 `deltaX` 直接生效，`deltaMode` 为「行 / 页」的设备会换算成像素。
  Chromium 在 Shift 按下时会把竖直滚动换算到 `deltaX` 上，所以两个来源要相加 ——
  只取其中一个在部分设备上会完全不动。
- 自检：拖动垂直滑块 120px → 画布下移 278px（与比例换算一致）、点击水平轨道跳到该处、
  竖滚与 Shift+竖滚各自只改一个轴且方向随滚动方向反转、内容小于视口时两条都隐藏。

#### 文字：顶栏跟随光标 + 放大后按屏幕分辨率重画
- **顶栏跟着光标/选区实时走**。编辑框里的光标一动（拖选、点选、方向键），顶栏的字体 / 字号 / 颜色
  就换成光标处（有选区则是选区内）那段文字**自己的**样式 —— 原先只在选中图层时同步一次整层样式，
  给选区单独改了字体或字号后顶栏还显示老值，看着像没生效。一段里混了多种字体或字号时显示
  「多种字体」与空字号（`styleSummary()`，按 run 边界切段比较，不必把整篇文字展开成数组）。
  控件只做**就地更新、绝不重建**选项栏，否则用户正在拖的取色器 / 滑块会被摘出 DOM 而中断。
  自检里既覆盖探针直接改选区的路径，也覆盖**真实鼠标**点两下换光标的路径。
- **放大后字形不再发糊（观感接近矢量）**。此前合成与文字光栅化都固定按文档分辨率做，放大视图时
  只是把文档像素整块拉大 —— 100% 以上越放越糊，800% 时字形边缘会出现明显的阶梯（锯齿）。
  现在放大时合成走**视口模式**：缓冲就是屏幕那一块、像素与屏幕一一对应，于是
  **任意放大倍率都是 1:1 采样**，而且显存只跟窗口大小有关（「整篇文档 × 屏幕比例」在 800% 时
  是几十倍显存）；文字纹理按 `scale.ts` 的档位（1 / 1.5 / 2 / 3 / 4 / 6 / 8）重画，并用
  1600 万像素的预算封顶（超预算退档，整层大字在高倍率下会略软）。缩小时仍按文档分辨率合成
  （缓冲比屏幕大，缩小采样质量更好）。图层效果的尺寸参数与调整图层的模糊 / 颗粒半径同步换算，
  视觉不变。**导出、吸管与保存 `.comp` 仍走文档分辨率**，官方格式互通不受影响。
  探针实测：8 倍放大下字形边缘的中间灰阶像素由 11346 降到 1217（约 −89%）。
  小提示：800% 以上画布会叠加「像素网格」细线（用于看清单个文档像素），觉得干扰可在视图菜单里关掉。
- **顺带修掉「组里的内容不显示」**。组是「先渲染到自己的离屏缓冲、再整体合成回来」的，
  而它合成回来时的采样矩阵此前写的是单位阵 —— 等于把缓冲里的**像素坐标**直接当 uv 用，
  组内所有像素都被判成越界而整组不可见。现在按缓冲尺寸归一化成 uv，并新增 `groupProbe`：
  100% 时白色像素 24000（＝文档 200×120），400%（视口模式）时 384000（＝800×480），两者都与预期完全一致。

#### 新建项目加入常用比例预设

- 五个预设：**1:1 / 4:3 / 3:2 / 16:9 / 9:16**，每个都有自己的图标与按钮。
  图标画的是「相同高度、不同宽高比」的框 —— 形状本身就提示了比例，再配文字标签；
  点一下把尺寸填进下面的输入框，用户仍可继续手改。

#### 新增启动起始页

- 启动后先看到一张**整屏起始页**（标题 + 三张卡片：新建项目 / 打开项目 / 导入图像 + 快捷键提示），
  **选完才进入工作区**。原先只是一个版本信息对话框，关掉就直接掉进空工作区，缺少「从哪开始」的引导。
- 起始页是全屏遮罩，会挡住后面的真实鼠标操作 —— 自检里必须先验证它再关掉（`dismissWelcome()`），
  否则「真实点击文字工具」这类探针会打在起始页上而误报失败（这一步已踩过）。

#### 同一图层可以叠加多个描边

- **描边从单值改成有序列表**：每个描边独立设置大小、颜色与内外侧，可以随时增删。
  旧的 `.comp` 里单个 `stroke` 字段仍会读入并并入列表（`strokeList()` 统一处理兼容），
  渲染与对话框共用这一套逻辑，不会出现两处各写一份的情况。
- **渲染为同心环**：按「先大后小」依次做形态学膨胀并叠色（新增 `STROKE_COMPOSE_FS`），
  后画的细描边覆盖在粗描边之上。探针实测两个描边（8px 红 + 4px 蓝）分别得到 9927 与 9334 个像素。
- **对话框支持多个描边**：每个描边一行（大小 / 颜色 / 内侧 / 删除），底部可继续添加；
  改动只重绘这一小块容器，不重建整个对话框 —— 否则会关掉用户正在操作的颜色面板。

#### 渐变叠加

- 在图层范围内按指定角度填充线性渐变，可调起止颜色与不透明度。实现上复用了「颜色叠加」那条
  通路：把停止点画成一张 256×1 纹理（`gradientTexture`），着色器里按 UV 采样。
- 坐标要**先换算到图层自己的 0–1 区间**再投影到渐变方向：直接用整块扩展画布的 UV 会让图层内
  几乎看不出变化；斜向还要按投影长度归一化（45° 时只有 ±0.707）。

#### 内侧描边的限制

内侧描边需要「腐蚀」而不是膨胀，与多层合成不是一条路，因此**多个内侧描边暂不支持** ——
多个描边目前只对外侧生效；内侧仍按单值处理。

#### 这一版暴露出的两个「探针比产品更可疑」的教训

- **多个描边一开始完全不出图**：诊断发现 `padding` 算成了 0 —— 留白的计算只看了旧的单值字段，
  没看新的数组，于是扩展画布等于图层本身、描边整圈被裁掉。**靠的是先把中间值记录下来再定位，
  而不是继续猜**（前面几轮猜坐标、猜纹理绑定，全猜错）。
- **渐变叠加其实一直是好的**：问题出在我的探针用「整屏左右平均亮度」去衡量一个**相对图层**的渐变，
  得出的结论是反向的。改用「纯黑/纯白像素计数」后立刻通过。

### v1.1.9

这一版把**文字工具**与**图层效果**从「能用」推到「可靠」，并统一了控件外观、补上 PSD 读写。
下面按主题整理 —— 期间修掉的许多问题彼此关联，按功能分组比按时间顺序更好读。

#### 文字工具

- **输入不再有重影**。编辑框里的字与画布上实时渲染的字原本叠在一起（`syncTextEditor` 用内联样式
  覆盖了 CSS 的透明设定），两套字形一叠加就像被拉长。现在编辑框文字透明，只留光标与虚线轮廓，
  真正做到所见即所得。
- **点空白不再冒出「文字」二字**。原来新建文字图层会填入「文字」占位，改完文字点空白收尾时就多出
  两个字来。现在新建为空（不渲染任何东西），输入后才画出真正的文字；一直没输入就自动删掉。
- **文字工具不再「点了没反应」**。`pointerdown` 的默认行为会把焦点交给画布，刚打开的编辑框立刻
  失焦、空图层随即被「未输入就删除」清掉。现在文字工具会 `preventDefault()`，并把聚焦延到下一帧、
  失焦确认也延后一拍。
- **编辑框内可以正常定位光标、拖选文字**。编辑框是画布的子元素，在它里面点击会冒泡到画布处理器；
  现在遇到来自编辑框的事件直接放行。
- **支持富文本：可以只改选中的那部分文字**。在编辑框里选中一段再改字体 / 颜色 / 字号，只作用于
  选区；没有选中才改整层。字体与颜色用官方的 `fontRuns` / `colorRuns` 存进 `.comp`，**官方可读**；
  字号官方没有对应字段，用扩展的 `sizeRuns` 保存（官方读到会忽略）。渲染改为逐字符测量与绘制，
  因此同一行里能混字体、颜色、字号。
- **文字描边改为沿字形外缘向外扩一层实色**。原先沿用图层效果那套「模糊 + 阈值化」近似，结果是发虚
  的。文字描边直接改用 Canvas 的 `strokeText`（`lineWidth = 2 × width`，正好一半落在字形外），
  并在画布四周留出余量，避免被切。

#### 字体

- **修掉「选了某个字体却毫无变化」**。系统报告的字体名常是「族名 + 字重」（如
  `阿里巴巴普惠体 3.0 105 Heavy`），而 CSS/Canvas 需要族名 —— 名字对不上时浏览器会**静默回退**，
  选了等于没选。实测 426 个条目里 90% 都是这样。现在加载时逐个实测：先用原名，失败就逐层剥掉
  尾部的字重 / 样式词再试，结果从 426 项收敛到 **371 项、且 0 项无效**。
- **修掉「部分字替换不成功」**。局部 `fontRuns` 会覆盖整层字体，改整层时没清掉它们，于是被覆盖的
  那几个字仍用旧字体。现在改整层字体 / 字号 / 颜色时会一并清掉对应的局部 run。
- **修掉「换字体后要再选一次才更新」**。`updateTextStyle` 原本在**应用样式之前**重建选项栏，
  而选项栏显示的是当前图层的样式 —— 那一刻还是旧值。现在重建放在应用之后。
- **字体选择器改为自绘**。原生 `<select>` 的绘制由系统接管，给 select / option 设字体都不生效，
  列表里看不出字体差异。现在按钮与每个列表项都用**各自的字体**渲染（实测 80 项 = 80 种字体），
  并带搜索框、面板自动收边。
- **字体列表不再乱码**。`reg.exe` 输出的是本地编码（中文系统为 GBK），被按 UTF-8 解码就成了乱码。
  改用 PowerShell 的 `InstalledFontCollection` 并显式指定 UTF-8 输出。
- **能看到后来安装的字体**。原先只读 `HKLM`，而选「仅为我安装」的字体会注册到 `HKCU`，永远列不出来；
  列表也只在启动时加载一次。现在两个注册表都读，下拉框旁还加了「刷新」按钮。
- 常见中文字体显示为「宋体（SimSun）」这样的中文名并排在最前。

#### 图层效果

- **图层描边改为形态学膨胀（实色外扩）**。原先描边与阴影共用「高斯模糊 + 阈值化」，边缘是摊开的
  渐变、看着发虚。现在新增 `DILATE_FS`：沿水平、垂直各取 ±radius 的**最大** alpha，得到精确外扩。
  探针实测描边像素的**完全不透明占比 = 1.0**（模糊方案远达不到）。阴影与发光仍走模糊 —— 发散
  本就是它们该有的样子。
- **效果入口挪到图层面板底部那一排**，与新建图层、蒙版、上下移放在一起，并配了专属图标（图层方块 +
  闪光），不再与「新建调整图层」共用。
- **移除文字工具选项栏里的「描边」**：描边归图层效果统一管理，不再有重复入口。

#### 界面与控件

- **界面令牌对齐 Morupixel 的设计系统**：图像是主角（UI 一律中性灰、退到后面）、用表面深度表示结构、
  **蓝色只用于状态**（`--accent` 淡蓝留给选择/焦点/进度，`--primary` 深蓝是每屏唯一主动作）。同时
  补齐字号、高度、圆角与间距令牌。旧变量名全部保留并映射到新灰阶，避免既有样式大面积失效。
- **统一所有原生控件的外观**。这些控件此前都没被 CSS 覆盖，一直沿用浏览器默认样式：
  - **数字 / 文本输入框**：系统主题色的聚焦描边 + number 自带的高度不一的上下箭头 → 统一到
    设计令牌，并用 `appearance: textfield` 去掉箭头（箭头样式无法自定义，留着必然是系统灰；
    数值仍可用键盘上下键与滚轮调整）。
  - **滑块**：`accent-color` 只能让控件套系统外观（亮蓝粗轨 + 大圆块）→ 改为 `appearance: none`
    完全自绘，4px 轨道 + 14px 圆点。
  - **颜色框**：原生控件自带内边距与白色粗边框 → 去掉。
  - **滚动条**：系统浅色粗白条 + 上下三角按钮 → 10px 圆角中性色滑块。
- **颜色选择器改为自绘**（`ui/colorpicker.ts`）。原生 `<input type="color">` 的取色面板由系统绘制，
  会弹出一个浅色窗口，风格无法统一。现在自己画：饱和度/明度方块 + 色相条 + 十六进制输入。
  选项栏三处（画笔 / 文字 / 形状）与效果对话框都已替换，代码里已无 `input[type=color]`。
- **修掉「取色器一拖动就关闭」**。起因是上一版为「选字体后立即更新」把 `buildOptionsBar()` 放进了
  `updateTextStyle` —— 而它会整体重建选项栏，把**用户正在操作的控件**从 DOM 里移走。现在改为就地
  调用字体选择器的 `setValue()`，对既有控件零干扰。
- **选择器面板不再超出窗口**：原先只处理了垂直方向，靠近窗口右侧时面板会伸出去被裁。现在两个方向
  都收边，并按 `offsetWidth/offsetHeight` 取真实尺寸（因此必须先显示面板、再测量定位）。
- **移除渐变工具**（工具栏的 G）；渐变映射（调整图层）保留。

#### 文件格式

- **新增 PSD 读写（分层 RGB 子集）**。用 `ag-psd` 处理格式细节，`src/renderer/psd.ts` 只做映射：
  - **打开**：走「导入图像…」，选 .psd 即可；逐层建图层，保留名称、像素、位置、不透明度、可见性
    与常见混合模式（24 种双向映射）。
  - **导出**：文件菜单新增「导出 PSD…」，把像素图层逐层写出（组与调整图层跳过 —— PSD 的简单层
    表达不了它们）。
  - **不支持**（刻意保守，避免误期）：图层蒙版、图层效果、文字/形状的可再编辑性（写出即光栅）、
    额外通道、CMYK / 16 位。读不了时给出明确说明，而不是静默失败。
  - 往返探针实测：120×90 文档 + 40×40 图层（位置 17,23）导出 1728 字节后读回，尺寸 / 位置 /
    图层名 / 中心像素 `0,200,80,255` 全部一致。

#### 渲染与编辑的底层可靠性

- **修掉整幅画面上下颠倒**（这是最关键的一处）。`QUAD_VS` 把 `vUV.y=0` 送到了 framebuffer 顶部，
  而纹理 `v=0` 在底部 —— 于是画布像素一直是对的、屏幕显示却是翻的。它连带表现出「框和图片不在
  一起」「拖动方向反了」等一连串假象。另外 `readDocumentPixels` 曾多翻一次，导致导出 PNG/JPEG 与
  吸管取色上下颠倒。
- **像素版本号改为全局单调递增**。原先每个画布各自从 0 计数，而文字重绘会**换成新的 canvas**、
  新画布又从头计数 —— 渲染器缓存里的旧版本号可能恰好与它相同，被判成「没变化」而跳过纹理上传，
  屏幕于是停在旧内容。现在任何一次改动都拿到从未用过的值。新增压力探针（连续 20 轮改字号、每轮
  都换新画布）断言屏幕每次都更新。
- **复制与粘贴**：`Ctrl+J` 与粘贴原先只抄位置、不抄尺寸/旋转/翻转；有选区时副本未裁到内容大小；
  复制组会丢子图层；`Ctrl+C/X/V` 在命令表里根本没有分支。现在有选区时只作用于选区内，没有则
  作用于整层。
- **选区与移动**：缩放角手柄的命中容差原本只按 `10/zoom` 算，视图缩小时会大到覆盖整个图层，
  想拖动却抓到角手柄（而缩放是对角固定的，于是「往右拖、左边界反而跟着缩」）；自动选择会抢走
  当前图层；吸附半径过强。三者都已修正。

#### 打包与验证

- **修掉免安装版启动变慢**。引入 `ag-psd` 时误放进 `dependencies`，打包器便把整个 `node_modules`
  也拷了一份 —— 而它早已被 bundle 进 `app.js`，运行时并不需要。移到 `devDependencies` 后，
  `app.asar` 从 **2.88 MB 降到 568 KB**、`win-unpacked` 从 389 MB 降到 368 MB。
  **教训**：会被 bundle 进产物的包要放 `devDependencies`。
- **测试方法本身修过两次**：
  - 早期探针全部**直接调用事件处理函数**，绕过了浏览器的默认行为，所以「点下去没反应」这类问题
    一直测不出来。现在改用 `sendInputEvent` 发送**真实鼠标事件**。
  - 探针之间会**互相污染**（遗留的编辑框吃掉真实点击；某个探针改过主题色没还原，导致后续「数白色
    像素」的断言恒为 0 而误报渲染卡住）。相关探针已改为自给自足、不依赖外部状态。
- 当前规模：59 项单元测试 + 66 条 e2e 探针，覆盖导入、复制、选区、文字、富文本、字体、图层效果、
  形状、参考线、修图、渲染方向与框/图对位、面板布局与控件外观、PSD 往返。

- **修复「选区完全不可见」**：渲染器此前从未绘制选区，框选/套索/魔棒只有状态没有画面。
  现在它们都会实时显示黑白蚂蚁线轮廓（在屏幕空间绘制，缩放平移都跟得住），

- **新增图层效果**：描边、投影、内阴影、外发光、内发光、颜色叠加，

### v1.0.2 — 修复覆盖层残留导致无法操作

- **修复「拖入后蓝色框不消失、无法继续操作」**：`.drop-overlay`、`.canvas-hint`、`.modal-root`
  三个覆盖层都设了 `display: grid`，而**作者样式表里的 `display` 会盖掉浏览器对 `hidden`
  属性的默认 `display: none`**（两者特异性相同，但作者样式优先）。后果是：拖放提示框常驻屏幕；
  **模态遮罩更是始终挂在窗口上、拦掉全窗口的鼠标操作** —— 这才是"无法操作"的直接原因
  （拖放走系统事件，所以仍能导入；但点击、切换工具、绘画全被遮罩吃掉）。
  现在用 `[hidden] { display: none !important }` 兜底。
- 拖放提示层的显隐不再用 `dragenter`/`dragleave` 计数（鼠标在窗口内各元素间移动会不断触发
  这对事件，计数必然失衡、框就卡住了），改为**指针真正移出窗口才隐藏**，并用 `drop`/`dragend` 收尾。
- 修复状态栏提前返回导致「从『文件 → 新建』开始，或拖入图像」提示在有图层后仍不消失的问题。

### v1.0.1 — 修复拖入与导入卡死

- **修复「无法拖入图片」**：主进程此前没有拦截 `will-navigate`，Electron 会把拖入的文件
  当作导航、直接替换掉整个页面（表现为毫无反应甚至白屏）；而且拖放只绑在画布上，
  拖到面板或工具栏同样会触发导航。现在拖放绑定到窗口级、同时只接管**文件**拖拽
  （不影响图层面板的拖拽排序），并显式拒绝一切页面导航与新窗口。
- **修复「导入图片后无法操作」**：撤销历史此前每次操作都会快照**全部图层**的像素。
  导入一张手机照片就是几十 MB，几十步历史足以把内存吃光、把应用拖死。
  现在改为**按需快照** —— 只有真正被改写的图层（画笔、擦除、渐变、删除图层/蒙版）
  才进入历史。实测导入 2000×1500 后连续 40 次操作耗时 **9ms**。
- 导入失败现在会弹出具体原因，不再静默失败。

## 与 Mac 版互通

`.comp` 是一个**文件夹**（macOS 上表现为文档包）：

```
示例.comp/
├── manifest.json
├── images/
│   ├── <图层UUID>.png
│   └── <图层UUID>.mask.png     # 蒙版（可选，8 位灰度）
└── QuickLook/Preview.jpg       # 保存时会被清理，由 Mac 版按需重建
```

- `manifest.json` 的 `format` 为 `com.compositor.project`，新保存写出**版本 11**，
  能读回版本 **1–11**。
- 图层数组**自下而上**排列；`transform` 描述图层在文档像素中的位置、尺寸、顺时针旋转与翻转。
- 图层图片必须命名为 `<图层ID>.png`（ID 大写），蒙版为 `<图层ID>.mask.png`。
- 保存遵循官方写入纪律：**先写图片**，再把 manifest 写到临时文件并**原子重命名**覆盖，
  最后清理不再引用的图片与 `QuickLook` 预览 —— Mac 版不会读到半个文件。
- 未识别的字段（官方后续版本新增的）会被**原样保留**，另存不丢数据。

单元测试覆盖了这些约定：官方示例能解析、round-trip 后语义不变、拼错的混合模式被拒绝、
版本门控生效、组与剪贴蒙版关系校验、资源缺失整份拒绝等。

## 与 Mac 版相比的已知差异

这是**可用的 MVP**，不是一对一移植。图层、文字、形状、图层效果、调整图层、选区、
修图工具、标尺/参考线/网格/吸附都已实现；以下是仍不对齐或做了近似的地方：

| 项目 | 状态 |
| --- | --- |
| 组的混色 | 组内先合成再按不透明度叠加（近似）；官方是**穿透（pass-through）**，组内使用非 Normal 混合模式时结果会有差异 |
| 图层效果的描边 | 膨胀/腐蚀用「模糊 + 阈值化」近似（官方在 GPU 上做形态学运算），极细描边或极小尺寸下可能与 Mac 版有出入 |
| 模糊类效果 | 采用 24 抽样可分离高斯，半径很大（数百像素）时精度不如官方 |
| 修图工具 | 用 Canvas 2D 实现，参数与撤销都对得齐，但在大尺寸图层上会明显慢于 Mac 版的 Metal 实现 |
| 修复画笔 | 用选区四周的邻域均值羽化填充（内容感知填充的简化版），对纯色/渐变背景效果好；官方能做结构感知 |
| PSD / PSB 导入 | 只导入 Chromium 能解码的合成预览，**不解析图层结构** |
| 选区约束绘画 | 未实现（画笔与修图工具不受选区限制） |
| 逐字着色 / 逐字换字体（`colorRuns` / `fontRuns`，v10/v11） | 数据完整保留并可往返，但暂不支持在界面里编辑 |
| 曲线拖拽编辑、Camera Raw 滤镜、直方图 | 未实现 |
| 参考线显示数量 | 画布上最多同时显示 16 条（官方数据仍可存 1000 条，读写不受影响） |
| 多文档标签页、自动更新 | 未实现 |

此外，调整图层的参数范围与算法是按官方文档重建的，个别数值可能与 Mac 版存在细微差别
（例如黑白与色彩平衡的通道权重、色阶的各通道独立设置目前只用 RGB 通道）。

## 架构

```
src/
├── shared/            # 与运行环境无关的纯逻辑（渲染进程与主进程共用，可直接单元测试）
│   ├── types.ts       # .comp v11 数据模型、官方混合模式与调整类型枚举、上限常量
│   ├── manifest.ts    # manifest 的解析、严格校验、序列化（含版本门控与未知字段保留）
│   ├── blend.ts       # 24 种混合模式的参考实现（着色器的「标准答案」）
│   ├── factory.ts     # 默认值工厂（恒等调整、新文档、新图层）
│   └── id.ts          # UUID
├── main/              # Electron 主进程
│   ├── main.ts        # 窗口、中文菜单、全部文件 IPC、--smoke 自检
│   ├── preload.ts     # contextBridge 暴露的受控 API
│   └── comp-store.ts  # .comp 的磁盘读写（原子 manifest 替换、清理孤儿资源）
└── renderer/          # 渲染进程
    ├── main.ts        # 应用主体：工具交互、命令、文件操作、渲染循环
    ├── gl/
    │   ├── shaders.ts # GLSL：24 种混合模式、蒙版、剪贴、12 种调整
    │   └── renderer.ts# 合成管线（FBO 乒乓、组递归、曲线 LUT、读回导出）
    ├── scale.ts       # 显示倍率档位：放大时按屏幕分辨率合成/光栅化（见下）
    ├── scroll.ts      # 画布滚动条的滑块长度/位置换算（纯函数）
    ├── state/editor.ts# 文档状态、图层操作、像素管理、撤销重做
    └── ui/            # 中文界面：工具栏、图层面板、属性面板、对话框、图标、工具指针（cursors.ts）
```

**合成管线**：自下而上遍历图层，每一趟把「已合成背景」与「本图层」按官方的混合模式与
W3C alpha 公式合并到另一个帧缓冲（乒乓双缓冲），因此任意图层都能正确看到它下面的所有内容。
组先渲染到自己的离屏缓冲再整体合成；调整图层读取当前背景、变换后写回。

**显示倍率（视口模式）**：放大视图时合成缓冲就是**屏幕那一块**（尺寸＝画布物理像素），
并把「文档 → 缓冲」的缩放与平移一起交给变换矩阵，因此缓冲像素与屏幕像素一一对应 ——
任意放大倍率都是 1:1 采样，字形与线条不会被放大的文档像素糊掉/出锯齿，显存也只跟窗口大小有关。
缩小时仍按文档分辨率合成（缓冲比屏幕大，缩小采样质量更好）。文字纹理另外按档位重画
（`scale.ts`，档位 1 / 1.5 / 2 / 3 / 4 / 6 / 8 + 像素预算），因为视口模式的缓冲分辨率
对整层大字仍然偏高。导出与吸管把视口模式关掉、恢复文档分辨率（`readDocumentPixels`），
所以输出与保存的 `.comp` 始终是文档分辨率。

`src/shared/blend.ts` 与 `src/renderer/gl/shaders.ts` 中的 `BLEND_LIB` 是同一套公式的
两份实现（CPU 参考版与 GPU 版），改动其一必须同步另一处 —— 单元测试锁住的是前者。
