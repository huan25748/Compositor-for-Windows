# Compositor for Windows

Mac 版 [Compositor](https://github.com/robbietilton/Compositor)（"The Photoshop alternative for Mac"，MIT 许可）的
**Windows 复刻版**。

上游是 Swift + SwiftUI + Metal 的原生应用；本复刻用 **Electron + TypeScript + WebGL2**
重写了它的图层合成引擎，并把界面完整本地化为**简体中文**。

最关键的一点：本程序**读写与 Mac 版完全互通的 `.comp` 项目格式**（官方 schema 版本 1–11）。

---

## 快速开始

```powershell
cd compositor-win
npm install
npm start        # 构建后启动
```

其它命令：

```powershell
npm run build       # 只构建（esbuild 打包主进程 / 预加载 / 渲染进程）
npm run typecheck   # TypeScript 类型检查
npm test            # 单元测试（.comp 读写、混合模式数学、校验规则）
npm run dist        # 打包 Windows 安装包（需要 electron-builder）
```

> 若 `npm install` 时提示 `esbuild` / `electron` 的安装脚本未执行，
> 运行 `node node_modules/electron/install.js` 以取得 Electron 二进制。

## 更新记录

### v1.1.9 — 文字工具修复（占位、重影、不显示、光标）＋移除渐变工具

- **修复免安装版启动变慢**。上一步引入 `ag-psd` 时把它放进了 `dependencies`，于是 electron-builder
  把整个 `node_modules` 也拷进了发行包 —— 但 esbuild 早已把 `ag-psd` **bundle 进 `app.js`**，
  运行时根本不需要它。结果是重复打包：免安装版每次启动都要多解压这几 MB 无用文件。
  把它移到 `devDependencies`（构建期依赖）后：`app.asar` 从 **2.88 MB 降到 568 KB**、
  `win-unpacked` 从 389 MB 降到 368 MB、portable 从 116 MB 降到 111 MB。功能不变（PSD 往返探针
  与全部 e2e 均照常通过）。**教训**：bundle 进产物的包要放 `devDependencies`，放进
  `dependencies` 会被打包器再拷一份。

- **新增 PSD 读写（分层 RGB 子集）**。用 `ag-psd` 处理格式细节，`src/renderer/psd.ts` 只做映射：
  - **打开**：走原有的「导入图像…」，选 .psd 即可。按 PSD 逐层建图层，保留名称、像素、位置、
    不透明度、可见性与常见混合模式；尺寸不同时按 PSD 新建文档。
  - **导出**：文件菜单新增「导出 PSD…」，把当前像素图层逐层写出（组与调整图层跳过 —— PSD 的
    简单层表达不了它们）。
  - **不支持**（刻意保守，避免误期）：图层蒙版、图层效果、文字/形状的可再编辑性（写出即光栅）、
    额外通道、CMYK / 16 位。读不了时会给出明确说明而不是静默失败。
  - 往返探针实测：120×90 文档 + 40×40 图层（位置 17,23）导出 1728 字节后读回，
    尺寸/位置/图层名/中心像素 `0,200,80,255` 全部一致。
  这一步引入了运行时依赖 `ag-psd`（约 290KB，已打进 app.js）。

- **修复选择器面板超出窗口被裁**。字体/颜色面板的定位只处理了**垂直**方向（下方放不下翻到上方），
  水平方向直接用按钮的左边缘 —— 面板靠近窗口右侧时就伸出去了。现在两个方向都收边，
  并按 `offsetWidth/offsetHeight` 取真实尺寸。**注意**：这也要求「先显示面板、再测量定位」，
  否则隐藏状态下量到的是 0，收边等于没做（两个选择器都已调整顺序）。
- **效果对话框里的颜色控件也换成自绘取色器**（上一版遗留的那一处）。至此代码里已无
  `input[type=color]`；效果未启用时复刻原来的禁用表现（半透明 + 不响应点击）。

- **颜色选择器改为自绘**（`ui/colorpicker.ts`）。原生 `<input type="color">` 点开后的取色面板
  由**系统**绘制，会弹出一个浅色窗口，风格完全无法统一。现在自己画：饱和度/明度方块 + 色相条 +
  十六进制输入，全部走设计令牌；拖动即时生效且不会中途关闭（面板挂在 body 上、只就地更新）。
  选项栏里的三处颜色控件（画笔 / 文字 / 形状）都已替换。**效果对话框里的颜色仍是原生控件**，
  尚未替换。
- **给「图层效果」设计了专属图标**（图层方块 + 闪光）。原先它与「新建调整图层」共用 `adjust`
  图标，两个按钮长得一样、不好区分。

- **修复「取色器一拖动就关闭」**。上一版为了「选字体后选择栏立即更新」，把 `buildOptionsBar()` 放进了
  `updateTextStyle` 的末尾 —— 而它是 `clear(bar)` 整体重建，于是：拖动颜色框 → 触发 input →
  改样式 → 重建选项栏 → 正在用的 `<input type="color">` 被移出 DOM → 原生取色器立即关闭。
  滑块同样会中招（拖动被打断），只是没有弹窗、不容易察觉。
  现在 `updateTextStyle` **不再重建选项栏**，只就地调用字体选择器的 `setValue()`；
  对既有控件零干扰，效果与之前一致。新增探针断言「改样式后颜色框仍是同一个 DOM 对象且仍在文档里」。
  另外修掉一处探针污染：某个探针改过 `textStyle` 颜色后没还原，导致后续「数白色像素」的探针
  恒为 0、误报成渲染卡住 —— 相关探针已改为显式设定颜色，不再依赖外部状态。

- **统一滑块、颜色框与滚动条**（同输入框一样，都是原生控件外观没被覆盖的问题）：
  - **滑块**：原先只给属性面板里的滑块设了 `accent-color`，选项栏里的（如画笔「硬度」）仍是
    浏览器默认的亮蓝粗轨 + 大圆块。`accent-color` 只能让控件套系统外观，无法统一风格，
    因此改为 `appearance: none` 完全自绘：4px 轨道 + 14px 圆点，颜色来自设计令牌。
  - **颜色框**：原生 `<input type="color">` 自带内边距与白色粗边框，现改为 `padding: 0` +
    1px `--stroke` 边框，色块四周留 3px。
  - **滚动条**：原先沿用系统浅色滚动条（粗白条 + 上下三角按钮），现改为 10px、圆角中性色滑块，
    并去掉三角按钮。（伪元素样式无法用 `getComputedStyle` 断言，这一项只能靠肉眼确认。）
  新增探针断言：滑块 `appearance` 必须是 `none`、颜色框 `padding` 必须是 `0px` 且边框为 1px。

- **统一数字 / 文本输入框外观**。原先只有 `.prop-row` 与 `.field` 内部的输入框有样式，
  **选项栏里的输入框完全没被覆盖** —— 于是它用着浏览器默认外观：系统主题色的聚焦描边，
  外加 number 输入自带的高度不一的上下箭头，和深色界面格格不入。现在把 `input[type=number]`、
  `input[type=text]` 统一到设计令牌（高 30、`--bg-sunken` 底、`--stroke` 边、聚焦转 `--accent`），
  并用 `appearance: textfield` 去掉原生箭头（箭头样式无法自定义，留着必然是系统灰；
  数值仍可用键盘上下键与滚轮调整）。新增探针断言：`appearance` 必须是 `textfield`、
  背景不能是默认白色、高度不能是 `auto`。

- **图层效果入口挪到图层面板底部那一排**（原在右侧属性面板），与新建图层、蒙版、上下移等放在一起；
  未选中可加效果的图层时会给出提示。
- **移除文字工具选项栏里的「描边」**。描边归图层效果统一管理，不再有「文字专有描边」这套重复入口；
  `textStroke` 字段保留，仍能读取既有 .comp 文件里的设置。
  待办：**同一图层自由添加多个描边**（需要把 `effects.stroke` 从单值改成有序列表、渲染改成多层膨胀
  合成、对话框加「添加描边」），属于较大改动，另行安排。

- **图层描边改用形态学膨胀（不再发散）**。原先图层描边和阴影共用同一套「高斯模糊 + 阈值化」
  近似，结果边缘是摊开的渐变、看起来发虚 —— 描边本该是实色外扩。现在新增 `DILATE_FS`：
  沿水平、垂直各取 ±radius 内的**最大** alpha（分离式），得到精确的实色外扩，膨胀半径就是
  描边宽度。阴影/发光仍走模糊（发散正是它们该有的样子）。
  探针实测：加 6px 描边后描边像素的**完全不透明占比 = 1.0**（模糊方案远达不到这个值）。
  下一步计划（按风险从低到高）：渐变叠加 → 图案叠加 → 斜面和浮雕。

- **修复「换字体后要再选一次，选择栏才更新」**。`updateTextStyle` 原先在**应用样式之前**就重建
  选项栏，而选项栏显示的是「当前图层的样式」—— 那一刻图层还是旧值，于是选择栏显示旧字体，
  第二次点击时图层已更新才显示正确。现在把重建挪到应用之后，并用 `finally` 保证提前 return 的
  分支（选区样式、无文字图层）也会重建。新增探针断言「选一次后选择器显示的名字 === 选中项」。

- **字体选择器改为自绘（撤回上一条「平台限制」的说法）**。上一条说「展开列表由系统绘制、无法
  跟随字体」——那只是原生 `<select>` 的限制，不是做不了。现在换成自绘选择器（`ui/fontpicker.ts`）：
  **按钮与每一个列表项都用各自的字体渲染**，并带搜索框（几百个字体里按名称/中文名过滤，
  一次最多列 80 项）。实测展开后 80 个列表项对应 80 种不同字体，选之前就能看出字形。
  面板挂在 `body` 上用 fixed 定位 —— 选项栏是横向滚动容器（`overflow-x: auto`），留在里面会被裁掉；
  因此重建选项栏时要清掉遗留面板，否则会累积看不见的旧面板（这个坑已踩并修好）。

- **字体栏的文字跟着所选字体走**。字体下拉框现在用所选字体渲染自己闭合时的那段文字，
  所以能直接看出当前是什么字体；补位项（当前字体不在系统列表里时临时加的那一项）也改用
  中文名显示（`宋体（SimSun）`），不再只显示 `SimSun`。
  已知限制：Windows 上原生 `<select>` 的**展开列表**由系统绘制，`<option>` 自带的字体设置
  不生效 —— 展开时各项仍是同一字体。要让列表里每一项都用各自字体预览，需要把下拉框换成
  自绘列表（工作量中等，可另行安排）。新增探针断言「下拉框的 fontFamily 跟随所选字体」。

- **修复「选了某个字体却没有任何变化」**。系统报告的字体名往往是「族名 + 字重」（例如
  `阿里巴巴普惠体 3.0 105 Heavy`），而 CSS / Canvas 需要的是**族名**；名字对不上时浏览器会
  **静默回退**到默认字体 —— 于是选了等于没选。实测下来 426 个条目里 90% 都是这种名字。
  现在加载字体表时逐个实测：先用原名，失败就逐层剥掉尾部的字重 / 样式词（含纯数字字重，
  `… 3.0 105 Heavy` → `… 3.0`）再试，两者都失败才丢弃。下拉框因此从 426 项收敛到 **371 项，
  且其中 0 项无效**。新增断言：「总数 ≥ 20」且「选了不生效的项数 = 0」。
  排查中还发现我第一版探针自身的回退链与基准不一致，会把有效字体误判成无效，已一并修正。

- **修复「部分字体替换不成功」**。富文本的局部字体 `fontRuns` 会覆盖整层字体：之前改整层字体时
  没有清掉它们，于是被 run 覆盖的那几个字仍用旧字体 —— 看上去就是「换是换了，偏偏有几个字不动」。
  现在改整层字体 / 字号 / 颜色时会一并清掉对应的局部 run，整层替换必然彻底。新增探针断言
  「换后局部 run 必须为 0」。

- **界面令牌对齐 Morupixel 的设计系统**（借鉴 `compositor-windows-main/docs/DESIGN_SYSTEM.md`）。
  原来的配色只有一个鲜艳蓝 `#4c8dff` 到处用；现在按它的三条原则重构：
  **图像是主角**（UI 一律中性灰、退到后面）、**用表面深度表示结构**（底 → 面板 → 按钮比面板亮 →
  输入框比面板暗）、**蓝色只用于状态**（`--accent` 淡蓝留给选择/焦点/进度，`--primary` 深蓝是每屏
  唯一主动作按钮，两者都不做装饰）。同时补齐字号（12/13/14/18）、高度（30/28/40/34）、圆角与间距
  令牌。旧变量名全部保留并映射到新灰阶，避免 738 行样式大面积失效。
  顺带修掉 `.btn.primary` 误用装饰性蓝色（改用 `--primary`）与一处硬编码的悬停色。
  注意：这一步只对齐了**令牌层**，多数控件尚未改用新令牌，观感变化有限。

- **像素版本号改为全局单调递增（根除「改了没反应 / 打上字不显示」的根因）**。原先每个画布各自
  从 0 开始计数 `version`，而文字图层重绘时会**换成新的 canvas 对象**、新画布又从头计数 ——
  渲染器缓存里记下的旧版本号可能恰好与它相同，于是被判成「没变化」而跳过纹理上传，屏幕上就
  停在旧内容。现在版本号来自一个全局单调计数器，任何一次改动都拿到一个从未用过的值，
  消费者不可能误判。
  说明：Morupixel 采用的是「改像素就整幅替换 backing buffer」，那套做法配合的是后台渲染与
  不可变快照；本项目是单线程共享画布，整幅拷贝换来不了收益，因此改用等价的全局版本号方案。
  新增压力探针（连续 20 轮改字号、每轮都会换新画布）断言屏幕每次都更新。

- **文字描边改成真正的「沿字形外缘向外扩一层实色」**。原先沿用了图层效果那套「模糊 + 阈值化」
  近似，结果是发散的、边缘发糊。文字描边本不该走 GPU 形态学运算 —— 现在直接用 Canvas 的
  `strokeText`：以字形轮廓为中心描 `2×width` 宽，其中一半落在字形外，正好等于向外扩 `width` 的
  实色描边。`measureText` 同时在画布四周各留出 `width`，避免描边被切掉。
- **文字工具顶栏新增「描边」宽度 + 颜色**，写入文字元数据的 `textStroke` 字段；选项栏会显示当前
  文字图层的描边值。该字段是本机扩展（官方 .comp 没有），官方读到会忽略。

- **字体列表全是乱码**：`reg.exe` 输出的是本地编码（中文系统是 GBK），却被按 UTF-8 解码，
  于是中文名字体全成了乱码。改用 PowerShell 的 `InstalledFontCollection` 直接取字体族名，并显式
  指定 UTF-8 输出 —— 现在拿到的是「阿里巴巴普惠体 3.0 105 Heavy」这样干净的名字，用户级安装的
  字体也在列表里。
- **选中的文字改不了字体**：选中一段文字后去点字体 / 颜色 / 字号控件，编辑框会失焦并被关闭，
  选中的那段随之丢失，结果只能改整层。现在焦点落在选项栏或工具栏时不关闭编辑器，选区得以保留，
  改动只作用于选中的那一段。

- **新增富文本：可以只改选中那部分文字**。在编辑框里选中一段文字，再改字体 / 颜色 / 字号，
  改动只作用于选中的部分，其余保持不变（没有选中时才改整层）。字体与颜色用官方的 `fontRuns` /
  `colorRuns` 字段存进 `.comp`，官方代码能正确读出；字号官方没有对应字段，用扩展的 `sizeRuns`
  保存 —— 官方读到会忽略（按整层字号显示），我们自己完整保留。渲染改为逐字符测量与绘制，
  因此同一行里可以混用不同字体、颜色和字号。
- **字体列表看不到新装的字体**：此前只读 `HKLM`（全局字体），而选「仅为我安装」的字体注册在
  `HKCU`，所以永远列不出来；另外列表也只在启动时加载一次。现在两个注册表都读，字体下拉框旁
  还加了「刷新」按钮 —— 装了新字体点一下就行，不用重启。

- **修掉编辑框内无法定位光标 / 选不中文字**：编辑框是画布的子元素，在它里面点击时事件会冒泡到
  画布处理器，而文字分支里的 `preventDefault()` 把「定位光标」这个默认行为也一并拦掉了。现在画布
  处理器遇到来自编辑框的事件直接放行：点哪光标到哪，也能正常拖选文本。
- **移除渐变工具**（工具栏的 G）。渐变映射（`图像 → 渐变映射…` 调整图层）保留不受影响。
- **点一下空白不再冒出「文字」二字**：文字工具在空白处按下会新建图层，而新建时默认填了
  「文字」这个占位内容——改完文字点空白想收尾，画面上就多出两个字来。现在**新建时内容为空**
  （画布 2×N、不渲染任何东西），输入后才画出真正的文字；若一直没输入就离开，这一层会自动删掉。
- **修掉真正的「重影」根因**：`syncTextEditor` 每次都用内联样式把编辑框里的文字设成图层颜色，
  **覆盖了** CSS 里的透明设定——所以编辑器里的字和画布上渲染的字一直同时可见，看着就是重影。
  现在绝不设置该颜色，编辑器只留光标与虚线轮廓，做到所见即所得。
- **修掉「文字工具没反应」**：空文字图层的画布只有 2px 宽，编辑框宽度按「图层宽度 × 缩放」
  算出来约 1.6px，窄到看不见；再点别处一失焦，这个空图层又被自动删掉。现在编辑框宽度有 240px
  下限、高度至少 1.4 行，确保可见、可输入、有焦点。
- **修掉「点下去连图层都不出现」**：`pointerdown` 的默认行为会把焦点交给画布，刚打开的编辑框
  立刻 `blur`，空图层随即被「未输入就删除」的逻辑清掉 —— 于是点一下什么都没留下。现在文字工具
  会 `preventDefault()`，并把聚焦延到下一帧、失焦确认也延后一拍，三处配合确保编辑框稳稳拿到焦点。
- **测试方法的修正（这条最重要）**：此前所有探针都是**直接调用事件处理函数**，绕过了浏览器的
  默认行为，所以「点下去没反应」这类问题一直测不出来，还让我误以为已经修好。现在增加了一条用
  `sendInputEvent` 发送**真实鼠标事件**的验证 —— 抓到这个 bug 的正是它。
- **修掉「打上字没有显示 / 改了没反应」**：图层画布重绘时可能换成**新的** canvas 对象，而新对象的
  `version` 从 0 重新计数，渲染器只比较 `version` 就会判成「没变化」而跳过纹理上传 —— 屏幕于是
  停留在旧内容（空白）。现在同时比较 canvas 身份，任何一次重绘都会真正上传到 GPU。
  对应探针会连续改两次文字，断言第二次也必须让屏幕像素发生变化。
- **编辑期间不换行**（`white-space: pre`）：画布上的文字按单行渲染，换行会让光标与文字对不上。
- **字体下拉框显示中文名**：常见中文字体显示成「宋体（SimSun）」这样的形式并**排在最前面**，
  其余按字母序；`option` 的 value 仍是真实字体名，渲染不受影响。
- 顺带补上 v1.1.7 里遗漏的两处改动：新建文字时全选内容、编辑已有文字时光标落到末尾
  （那两处 edit 当时被中断，没写进文件）。
- **新增两个探针**：一个断言新建文字时画布不含任何像素，另一个断言编辑框「存在、够宽、
  文字透明、已获得焦点」——上面这两个缺陷以后不会再无声回归。

### v1.1.1 – v1.1.7 — 渲染方向、复制与文字（整合）

这一批修复的问题**相互叠加**，常常表现为同一个现象，逐条排查容易跑偏，因此按主题整合如下。

**渲染方向（最关键的一处）**

整幅画面上下颠倒：`QUAD_VS` 把 `vUV.y=0` 送到了 framebuffer 顶部，而纹理 `v=0` 在底部，
于是画布像素一直是对的、屏幕显示却是翻的。它连带表现出「框和图片不在一个地方」、
「拖动方向反了」等一连串假象——这也是前几轮反复找不到真凶的原因。
另外 `readDocumentPixels` 曾多做一次翻转，导致导出 PNG/JPEG 与吸管取色上下颠倒。两处均已修正。

**复制与粘贴**

- `Ctrl+J` 与粘贴原先只抄位置，不抄尺寸/旋转/翻转 —— 缩放过的图层一复制就缩回原始大小。
- 有选区时副本没有裁到内容大小 —— 框比内容大出一圈，看起来就是「框在的地方没有图片」。
- 复制组时递归出的子图层没有插进 manifest —— 复制一个组会把组里的内容整片丢掉。
- `Ctrl+C` / `Ctrl+X` / `Ctrl+V` 在命令表里根本没有分支，按下去没有任何反应。

现在：有选区时只作用于选区内（`Ctrl+J` 还会把副本裁到内容大小），没有选区则作用于整层。

**移动与选区**

- 缩放手柄的命中容差原本只按 `10/zoom` 算，视图缩小时会大到覆盖整个图层 —— 想拖动却抓到了
  角手柄；而缩放是**对角固定**的，于是「往右拖、左边界反而跟着缩」。现在容差取
  「屏幕 10px」与「图层短边 1/4」中的较小值。
- 自动选择会抢走当前图层 —— 改为**优先保持当前图层**，只有当前图层在点击处确实透明时才向下层找。
- 吸附半径加上限 `min(6/zoom, 20)`，避免视图很小时吸附过强、像拖不动。

**文字**

- 内联编辑器有底色与浅色全选高亮，而且编辑器里的字与画布渲染的字叠在一起 —— 现在编辑器文字
  设为透明，只留光标与虚线轮廓，做到所见即所得。
- 字体下拉框改为读取系统真实安装的字体（本机 467 个，此前是内置的 11 个）。
- 缩放文字图层时按比例重绘字号，不再被拉伸变形。

**顺带新增的能力**

- 拖动四角手柄调整图层大小（`Shift` 锁定比例）。
- 修掉一个会让渲染进程完全起不来的问题：变换框着色器里用 GLSL 保留字 `half` 当变量名，
  编译失败会让整个渲染器构造抛错（现在 `--smoke` 会直接打印渲染进程的报错）。
- **帮助 → 诊断信息**：输出操作日志、图层列表与活动图层像素采样，用于精确定位问题。

**验证**

30 项单元测试 + 24 项 e2e 探针（覆盖导入、复制、选区、文字、图层效果、形状、参考线、修图、
渲染方向与框/图对位），全部在打包后的 exe 上复跑通过。

### v1.1.0 — 补齐 Mac 版的主要功能

- **修复「选区完全不可见」**：渲染器此前从未绘制选区，框选/套索/魔棒只有状态没有画面。
  现在它们都会实时显示黑白蚂蚁线轮廓（在屏幕空间绘制，缩放平移都跟得住），
  裁剪与形状拖动时也会显示预览框。
- **新增文字工具**：点击画布新建文字图层、双击可再次编辑，选项栏可调字体、字号、颜色、
  对齐、字距、行距；样式写入官方 `text` 元数据，与 Mac 版互通。
- **新增形状工具**：矩形、圆角矩形、椭圆、直线；保存为官方 `shape` 元数据，
  改尺寸或颜色时按元数据重画，而不是把位图拉伸变形。
- **新增图层效果**：描边、投影、内阴影、外发光、内发光、颜色叠加，
  在 GPU 上按官方顺序合成，参数写入官方 `effects` 记录。
- **新增修图工具**：仿制图章（Alt 点击设源点）、修复画笔、涂抹、液化。
- **新增画布辅助**：标尺（从标尺往外拖即可创建参考线）、参考线（官方 `guides` 字段）、
  网格与像素网格，以及对画布边缘/中心、参考线、网格的吸附。

### v1.0.2 — 修复覆盖层残留导致无法操作

- **修复「拖入后蓝色框不消失、无法继续操作」**：`.drop-overlay`、`.canvas-hint`、`.modal-root`
  三个覆盖层都设了 `display: grid`，而**作者样式表里的 `display` 会盖掉浏览器对 `hidden`
  属性的默认 `display: none`**（两者特异性相同，但作者样式优先）。后果是：拖放提示框常驻屏幕；
  **模态遮罩更是始终挂在窗口上、拦掉全窗口的鼠标操作** —— 这才是"无法操作"的直接原因
  （拖放走系统事件，所以仍能导入；但点击、切换工具、绘画全被遮罩吃掉）。
  现在用 `[hidden] { display: none !important }` 兜底。
- 拖放提示层的显隐不再用 `dragenter`/`dragleave` 计数（鼠标在窗口内各元素间移动会不断触发
  这对事件，计数必然失衡、框就卡住了），改为**指针真正移出窗口才隐藏**，并用 `drop`/`dragend` 收尾。
- 修复状态栏提前返回导致「从『文件 → 新建』开始，或拖入图像」提示在有图层后仍不消失的问题。

### v1.0.1 — 修复拖入与导入卡死

- **修复「无法拖入图片」**：主进程此前没有拦截 `will-navigate`，Electron 会把拖入的文件
  当作导航、直接替换掉整个页面（表现为毫无反应甚至白屏）；而且拖放只绑在画布上，
  拖到面板或工具栏同样会触发导航。现在拖放绑定到窗口级、同时只接管**文件**拖拽
  （不影响图层面板的拖拽排序），并显式拒绝一切页面导航与新窗口。
- **修复「导入图片后无法操作」**：撤销历史此前每次操作都会快照**全部图层**的像素。
  导入一张手机照片就是几十 MB，几十步历史足以把内存吃光、把应用拖死。
  现在改为**按需快照** —— 只有真正被改写的图层（画笔、擦除、渐变、删除图层/蒙版）
  才进入历史。实测导入 2000×1500 后连续 40 次操作耗时 **9ms**。
- 导入失败现在会弹出具体原因，不再静默失败。

## 与 Mac 版互通

`.comp` 是一个**文件夹**（macOS 上表现为文档包）：

```
示例.comp/
├── manifest.json
├── images/
│   ├── <图层UUID>.png
│   └── <图层UUID>.mask.png     # 蒙版（可选，8 位灰度）
└── QuickLook/Preview.jpg       # 保存时会被清理，由 Mac 版按需重建
```

- `manifest.json` 的 `format` 为 `com.compositor.project`，新保存写出**版本 11**，
  能读回版本 **1–11**。
- 图层数组**自下而上**排列；`transform` 描述图层在文档像素中的位置、尺寸、顺时针旋转与翻转。
- 图层图片必须命名为 `<图层ID>.png`（ID 大写），蒙版为 `<图层ID>.mask.png`。
- 保存遵循官方写入纪律：**先写图片**，再把 manifest 写到临时文件并**原子重命名**覆盖，
  最后清理不再引用的图片与 `QuickLook` 预览 —— Mac 版不会读到半个文件。
- 未识别的字段（官方后续版本新增的）会被**原样保留**，另存不丢数据。

单元测试覆盖了这些约定：官方示例能解析、round-trip 后语义不变、拼错的混合模式被拒绝、
版本门控生效、组与剪贴蒙版关系校验、资源缺失整份拒绝等。

## 与 Mac 版相比的已知差异

这是**可用的 MVP**，不是一对一移植。图层、文字、形状、图层效果、调整图层、选区、
修图工具、标尺/参考线/网格/吸附都已实现；以下是仍不对齐或做了近似的地方：

| 项目 | 状态 |
| --- | --- |
| 组的混色 | 组内先合成再按不透明度叠加（近似）；官方是**穿透（pass-through）**，组内使用非 Normal 混合模式时结果会有差异 |
| 图层效果的描边 | 膨胀/腐蚀用「模糊 + 阈值化」近似（官方在 GPU 上做形态学运算），极细描边或极小尺寸下可能与 Mac 版有出入 |
| 模糊类效果 | 采用 24 抽样可分离高斯，半径很大（数百像素）时精度不如官方 |
| 修图工具 | 用 Canvas 2D 实现，参数与撤销都对得齐，但在大尺寸图层上会明显慢于 Mac 版的 Metal 实现 |
| 修复画笔 | 用选区四周的邻域均值羽化填充（内容感知填充的简化版），对纯色/渐变背景效果好；官方能做结构感知 |
| PSD / PSB 导入 | 只导入 Chromium 能解码的合成预览，**不解析图层结构** |
| 选区约束绘画 | 未实现（画笔与修图工具不受选区限制） |
| 逐字着色 / 逐字换字体（`colorRuns` / `fontRuns`，v10/v11） | 数据完整保留并可往返，但暂不支持在界面里编辑 |
| 曲线拖拽编辑、Camera Raw 滤镜、直方图 | 未实现 |
| 参考线显示数量 | 画布上最多同时显示 16 条（官方数据仍可存 1000 条，读写不受影响） |
| 多文档标签页、自动更新 | 未实现 |

此外，调整图层的参数范围与算法是按官方文档重建的，个别数值可能与 Mac 版存在细微差别
（例如黑白与色彩平衡的通道权重、色阶的各通道独立设置目前只用 RGB 通道）。

## 架构

```
src/
├── shared/            # 与运行环境无关的纯逻辑（渲染进程与主进程共用，可直接单元测试）
│   ├── types.ts       # .comp v11 数据模型、官方混合模式与调整类型枚举、上限常量
│   ├── manifest.ts    # manifest 的解析、严格校验、序列化（含版本门控与未知字段保留）
│   ├── blend.ts       # 24 种混合模式的参考实现（着色器的「标准答案」）
│   ├── factory.ts     # 默认值工厂（恒等调整、新文档、新图层）
│   └── id.ts          # UUID
├── main/              # Electron 主进程
│   ├── main.ts        # 窗口、中文菜单、全部文件 IPC、--smoke 自检
│   ├── preload.ts     # contextBridge 暴露的受控 API
│   └── comp-store.ts  # .comp 的磁盘读写（原子 manifest 替换、清理孤儿资源）
└── renderer/          # 渲染进程
    ├── main.ts        # 应用主体：工具交互、命令、文件操作、渲染循环
    ├── gl/
    │   ├── shaders.ts # GLSL：24 种混合模式、蒙版、剪贴、12 种调整
    │   └── renderer.ts# 合成管线（FBO 乒乓、组递归、曲线 LUT、读回导出）
    ├── state/editor.ts# 文档状态、图层操作、像素管理、撤销重做
    └── ui/            # 中文界面：工具栏、图层面板、属性面板、对话框、图标
```

**合成管线**：自下而上遍历图层，每一趟把「已合成背景」与「本图层」按官方的混合模式与
W3C alpha 公式合并到另一个帧缓冲（乒乓双缓冲），因此任意图层都能正确看到它下面的所有内容。
组先渲染到自己的离屏缓冲再整体合成；调整图层读取当前背景、变换后写回。

`src/shared/blend.ts` 与 `src/renderer/gl/shaders.ts` 中的 `BLEND_LIB` 是同一套公式的
